# Adaptive spatial exploration

The solid explorers now use [`GpuSpatialExplorer`](../spatialGpu/README.md): the Sierpinski tetrahedron and pyramid, polyhedron flakes, Jerusalem cube and both Koch surfaces. Their visible detail, picking and collision queries run on the GPU. `SpatialExplorer` retains the worker-based path for the 3D Hilbert curve. Other finite construction players continue using the existing scene and polyline renderers. The L-system Explorer is independent.

The mesh construction and collision-shell details below describe the retained geometry reference and the Hilbert renderer, rather than the active solid flythroughs. The solid geometry helpers remain covered by the finite-generator tests.

Romanesco uses `GpuSpatialExplorer` with analytic round-cone intersections and a retained-parent union. Its eight/thirteen spiral lattice repeats around each floret. The finite construction player uses the same GPU renderer at fixed ranks, growing only the newest generation from its base. Neither Romanesco view generates a triangle mesh. See the [GPU renderer contract](../spatialGpu/README.md).

The camera stores a target in BigInt fixed point and a base-two zoom exponent. Precision grows with zoom, retaining 160 guard bits. Mesh vertices reach WebGL only after subtraction of the target. The limit is 240 zoom doublings; this is a practical depth bound. Input coefficients for irrational constructions retain the precision of the existing JavaScript generators.

Geometry builds in a worker, with at most one request running and the latest pending request retained. Conservative bounds include descendants: two edge lengths for triangular Koch patches, three half-widths for quadratic patches, and the seed circumradius for flakes and Jerusalem cubes. Frustum tests use planes before perspective projection. If a frame exceeds its geometry budget, the whole frame retries with a coarser screen tolerance; branches are never intentionally dropped from a displayed frame. Defaults are sixteen CSS pixels for solid descendant bounds, 1.5 CSS pixels for the Hilbert curve, and 240,000 triangle vertices. Solid outlines fade on triangles narrower than ten framebuffer pixels, disappearing below three, so tiny faces do not become stroke colour. Moving frames reuse the last successful tolerance; an idle request retries the finer default.

The GPU depth buffer resolves overlap; `EXT_frag_depth`, when available, gives logarithmic depth to avoid distant face flicker. A packed normal/depth pass supplies screen-space contact shading (Soft or Strong), depth lighting and a local fog horizon. Hilbert retains its near/far colors and opacity. This contact shading uses visible neighbours; the voxel renderer’s Minecraft mode still uses exact voxel occupancy. Polygon outlines exclude fan triangulation diagonals. While a worker prepares detail, a change of camera frame transforms the last mesh immediately. Picking uses that same transform, so wheel gestures during refinement keep their model-space anchor. Completed worker frames are accepted during continuous movement before the next pending request starts. Context restoration recreates resources, and unmount terminates the worker and removes event listeners. Rendering requires WebGL and standard derivatives.

Flake children use the existing mesh vertices and contraction ratios. Jerusalem children have eight corner cubes at ratio `sqrt(2)-1` and twelve edge cubes at its square; their ranks advance by one and two respectively. Triangular Koch patches reproduce the existing midpoint tetrahedron construction. Quadratic patches reproduce eight flat squares and five raised cube faces. Hilbert octant symmetries are derived from the existing Skilling generator. Adaptive leaves join at the limiting octant endpoints.

`AttractorDetail` retains double-precision orbit checkpoints. Each user time interval uses four RK4 substeps. Its cubic Hermite segments use the differential equation at both endpoints and subdivide until projected midpoint and quarter-point deviations from the chord are at most 0.35 CSS pixels, within a bounded recursion and point budget. Bezier control hulls cull segments before projection, including intervals crossing the camera plane. Explicit break markers prevent drawing connections across culled intervals. Zoom adds later trajectory coverage up to 160,000 user intervals; normalization remains fixed to the opening orbit. Rendering retains at most 180,000 points. The camera allows 24 zoom doublings. This reveals more sampled flow, not an exact infinite attractor. Animated trails retain their existing finite-buffer behaviour.

Flight is the opening navigation mode on these pages. Click/Enter captures the mouse; WASD/arrows move, Space/E rises, C/Q descends and Shift boosts. Escape, blur, context loss and unmount release capture and held input. Touch uses the existing Move/Look sticks. Reset view restores the opening camera, releases capture and held input, and enables flight controls. Shared views retain their fixed-point position and legacy navigation mode until reset.

Flight turns and working-scale changes preserve the physical eye. A separate 36,000-vertex collision shell retains nearby surfaces in all directions. Steps cover at most one fifth of measured clearance; Koch shells also pad for unresolved descendants. Movement slows and working precision increases near a wall, while recovery into wider space is gradual. The atmosphere uses the voxel renderer’s critically damped scale, saved independently from precision. The shell is conservative: unresolved gaps open after a later worker refinement. It is not the voxel renderer’s analytic grid traversal. Mandelbulb instead uses its distance estimate; trajectories use picked curve proximity, with no enclosed solid implied.

Polyline picking runs in the existing render worker and returns a perspective-correct model point on a visible segment. The controls use this actual trajectory depth when zooming. Saved views include the fixed-point target and exponent, separately from the ordinary controls.

Mandelbulb uses the same target controls with a separate shader limit of twelve zoom doublings. The shader increases orbit iterations with zoom, up to 48, and allows 256 ray steps. Its world-space hit tolerance floors at `2e-7`; single-precision shader arithmetic bounds useful detail. CPU distance estimates anchor gestures to the visible surface. This is deeper numerical exploration, not arbitrary-precision Mandelbulb rendering.

Validation: `node --test tests/spatial-zoom.test.mjs`. The fixtures compare ray intersections with independent finite generators, unequal Jerusalem ranks, Hilbert endpoint continuity, deep camera coordinates, worker-frame transforms, trajectory coverage/refinement, perspective picking, and Mandelbulb surface anchors. Run `pnpm exec tsc --noEmit` and `pnpm build` after changes affecting the renderers or worker protocol.

Depth lighting uses an upper-left view-space key and smooth near-field relief before the existing haze. `lighting.ts` starts the relief ramp at a fixed model-space reference volume; it never follows the generated mesh or LOD. Reference planes are subtracted from the BigInt camera target before conversion, preserving them near deep boundaries. The ramp uses the independently damped visual scale, stays continuous on entry and has a 55% floor. Solid outlines use matching illumination at 18% strength. Classic lighting and curve palettes retain their existing composition.
